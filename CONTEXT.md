Unit symbols (`km`, `bar`, `°C`) are not translated.

Address is **du** everywhere. A Sie addressing the reader is a bug; `Sie`/`Ihre` meaning "they" is fine.

Preset templates are copied into the user's data when picked, so their text is written in the language of the moment it was picked and stays as written after a language switch (Phase 14). The generic **task templates** (`taskPresetsFor` in `lib/utils/task_presets.dart`) are translated: the name and note come from the `taskTemplate…` ARB keys by template key, and a brand-only template or a catalog override takes its YAML text in the catalog language. The **adjustment templates** of the Add Adjustment sheet and the **rider attribute templates** are translated the same way (`lib/utils/adjustment_presets.dart`, ARB keys `adjustmentTemplate…` / `riderTemplate…`): established terms stay as they are (`LSC`, `HSR`, `SAG`, `Flipchip`, `FTP`), descriptive names are translated (`Zugstufe`, `Druckstufe`, `Fahrergewicht`). Nothing language-dependent is matched by its text: the setup guide, the catalog merge and `adjustmentRole` use the language-neutral `presetKey`; "already added" accepts a template's name in any supported language (`adjustmentPresetNameVariants`); and the stored riding style option (`Comfort` / `Komfort`, `Balanced` / `Ausgewogen`, `Race`) is read back in any language by `guideRidingStyleOfOption`. Adjusters built from the component catalog are translated in the YAML (below); SAG shares the template. The text the app generates around a template, like the `Empfohlenes Intervall: …` line in a task's notes or the note lines of a component created from the catalog (`Modelljahr: …`, `Setup-Anleitung: …`), is written in the language of the moment it was created.

Catalog text is translated the same way: it is translated when a catalog entry is picked and stored as written, and existing components are never translated after a language switch. The translations live **inline** in the brand YAML as `<field>_<lang>` siblings (`name_de`, `options_de`), so one entry holds all its text; the parser reads only English plus the active language (`ComponentCatalogRepository` is given a function that tells the app language and compares it on every access, re-parsing only the loaded types when it changed; no one has to notify it), a missing translation falls back to English, and `test/component_catalog_l10n_test.dart` fails for a shipped language (`shippedCatalogLanguages`) with a missing one. What is translated: adjuster `name`/`notes`/`options`, damper `description`, `missing_adjustments`, node `note` and `category`, the spec values `stanchion` and `spring`, guide `label` and rule `note`, brand task `name`/`source`, and the `review` summaries and `fix` texts of `changes:`. What is not: brand and model names (`brand`, node `label`, damper `name`), size labels and mounts, ids, units, urls, a damper's hidden `note`/`source`, and the English option cells of a setup guide (`value: Open`), which name the adjuster's English option by its place. Nothing is matched by catalog text across languages: the setup guide evaluator and the preset merge use the `presetKey` plus the option's place, so a component made in English still evaluates against the German catalog and the other way round. A catalog adjuster that has a generic template (`fork:rebound`, `shock:hsc`) is named like the template (`Zugstufe`); `tool/catalog_l10n.dart` lists what is missing. See `data/component_presets/SCHEMA.md`, "Translations".

Catalog numbers keep a dot in every language where they are part of a name: size labels (`210x52.5`), option chips, the eye-to-eye headers and the option summary of a suggestion (`52.5 / 55 mm`). They are model nomenclature, the labels are parsed once and cached, and the same number would otherwise read `52,5` in one place and `52.5` in the next. Numbers in the note of a component created from the catalog (`Hub: 52,5 mm`) are plain text for the rider and follow the language.

The Strava link text `View on Strava` stays English in every language, because Strava's brand guidelines word it that way. The same goes for `Powered by Strava`.
